# LW-141: Hosted categoriser fallback with a literal payload preview

Status: planned. Minted 2026-10-25 by the research programme (docs/51).
Milestone: M2. Priority: P2.
Dependencies: LW-117, LW-111, LW-140.
Owner decision HUMAN_TODO q-5 bounds hosted scope to names only (docs/51 section 2.4); this item does not widen it.

## Scope
Add a hosted categoriser as the last stage of the cascade, reached only on abstention and only once q-5's preconditions hold (docs/51 section 4.8, stage 4). Before anything leaves the machine, Loomward shows the literal payload that would be sent. Disclosure levels are chosen by the owner and are never escalated silently. Results are cached by the digest of provider, model, prompt version, schema and the disclosed payload. Ask already records the body SHA-256 before a send but shows no preview (docs/51 section 2.4), so closing that gap is this item's first step.

## Acceptance evidence
A test asserts that no hosted request is sent without a preview whose digest matches the sent payload. A disclosure-level increase requires a new owner action and is refused otherwise. The cache key changes when the provider, model, prompt version, schema or payload changes. An offline or refused provider leaves the local answer or the abstention visible (invariant 4). Tests use synthetic payloads only and make no live provider call.
