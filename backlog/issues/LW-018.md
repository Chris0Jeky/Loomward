# LW-018: Connect the Tauri shell to read-only native view models

Status: planned local backlog item, not a published GitHub issue.
Milestone: M1. Priority: P0.
Dependencies: LW-011, LW-017.

## Problem and deliverable
Turn the synthetic shell scaffold into a real observation UI using narrowly scoped commands. Do not broaden Tauri plugins to bypass the API design.

## Proposed ownership
`native/; ui/transport.js; ui/`
Read `docs/12-ux.md` and `AGENTS.md` before implementation. Shared protocol/schema changes require coordination with their owner.

## Acceptance criteria
Windows WebView2 loads assets under CSP; real/synthetic/imported modes stay distinct; disconnect shows unavailable rather than demo; metadata queries and feedback work; file/process mutation commands remain absent.

## Implementation and evidence
Write the failing regression or native fixture first. Implement the smallest complete interface that satisfies these criteria. Run the complete applicable Python/Rust/UI suite and the named Windows cases. Record exact commands, platform, fixture scope and results in a new evidence file. Update implementation status and the handoff checkpoint; do not call a test passed because a workflow was merely authored.

## Boundary
No additional capability is implicitly authorised by this issue. Keep unrelated file/process mutations, elevated privileges, cloud transfer and public publication off. Use only disposable data for native-effect experiments. When a required platform capability is absent, report a named limitation rather than substituting synthetic success.
