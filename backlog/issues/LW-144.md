# LW-144: Measure hashing and I/O costs per storage class

Status: planned. Minted 2026-10-25 by the research programme (docs/51).
Milestone: M6. Priority: P2.
Dependencies: LW-064.
Owner decisions HUMAN_TODO q-47 and q-48 (2026-10-25) bind this programme (docs/51 header).

## Scope
Measure what hashing and I/O really cost per storage class, so later design choices rest on numbers (docs/51 sections 2.2, 2.7 and 5 P5; X8). The sweep covers I/O size and queue depth on the USB HDD and records wake latency after selective suspend, with no OS power policy change (invariant 2). It measures whether SHA-256 ever limits an HDD: BLAKE3 is adopted only if measured, and XXH3 is considered only for candidate bucketing. Corpora are generated, 32 to 128 GiB per storage class and never on `C:`, in lab folders only. The H: transfer matrix (up to 300 GB) runs only in a dedicated lab folder on `H:`, on the owner's go-ahead, never against owner data (docs/51 section 10).

## Acceptance evidence
Recorded tables per storage class: sustained transfer throughput, hash throughput, I/O size and queue-depth results, and wake latency, each with its corpus size and hardware class (docs/51 X8). The SHA-256 versus BLAKE3 choice follows a measured limit, or stays SHA-256 and says so. No OS power setting or driver setting is changed. Corpora are generated and never committed to Git.
