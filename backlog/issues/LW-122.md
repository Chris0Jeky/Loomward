# LW-122: Publish a rolling nightly channel and an opt-in updater

Status: in_progress. Minted from the owner decisions of 2026-10-12.
Milestone: M1. Priority: P1.
Dependencies: LW-057.
Owner decision HUMAN_TODO q-33 (2026-10-12); Owner decision HUMAN_TODO q-30 (2026-10-12).

## Scope
Every merge to main publishes a rolling, unsigned nightly pre-release. The opt-in updater (a Check for updates button and an optional check-on-start toggle, off by default) gains a nightly channel the owner enables on this PC and Kraspyon. State is copied before every migration and the previous nightly stays restorable. Invariant 2 is unchanged by the updater; invariant 8 names the nightly as owner-authorised and is edited by the session driver, not by this issue.

## Publication and installation are separate gates (follow-up to #422)
An unsigned Windows preview may be published without making it eligible for in-app installation. Distinguish `publish_unsigned_preview` from `update_eligible`. The latter remains false, with an explicit Unavailable reason, until the owner supplies the updater signing key (HUMAN_TODO q-30), the app pins its trusted public verifier, immutable artifact identity and signed metadata are bound to the package, and the state-compatible rollback policy is reviewed. A reachable HTTPS URL or a checksum obtained from the same mutable manifest is not publisher authentication.

Windows Authenticode signing (q-28) and cryptographic updater-package verification (q-30) are different controls. Do not weaken signature verification to make an unsigned nightly installable. Any new Tauri updater permission or runtime capability needs its own reviewed implementation; this backlog item does not silently grant it. A user-triggered check may explain why a published build is ineligible, but must not install it.

Rollback couples the selected prior binary to its matching pre-migration state snapshot. Never run an older binary against a newer, incompatible state schema as a substitute for the restore drill. Interrupted state migration must retain the last recoverable binary/state pair and report a recoverable or needs-attention state rather than a successful update.

## Acceptance evidence
A workflow run publishing a nightly from main; no check happens unless the owner triggers or enables it; no installation happens without authenticated package verification and an eligible state transition. Test missing key, missing signature, bad signature, valid signature with a mismatched artifact, valid authenticated update, rollback with the matching state snapshot, and a crash after state migration begins. Record the restore-previous-nightly drill and state-copy evidence. The updater signing key stays an owner action (HUMAN_TODO q-30); absent owner setup is reported UNAVAILABLE, not passed.
