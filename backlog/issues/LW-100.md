# [LW-100] Gate release claims against executable capability evidence

**Status:** planned continuation; the v0.2 reference is supporting evidence, not completion of this production issue.
**Milestone:** M2I. **Priority:** P0.
**Depends on:** LW-057, LW-063, LW-065, LW-096, LW-097.

## Outcome and boundaries

Create a release capability matrix that distinguishes reference, simulated, native-tested, host-tested and production-supported states. Require per-platform test evidence, licence review, installer provenance and explicit unavailable features before public release.

## Owned files and interface

Create or modify: `scripts/check_release_claims.py; docs/RELEASE-CAPABILITIES.json; tests/release/`. These paths name the intended implementation area; new directories are not claimed to exist.

`verify_claims(ClaimManifest, EvidenceIndex) -> QualificationReport` rejects unsupported success assertions.

Read `docs/23-expansion-overview.md`, `docs/25-control-evidence-architecture.md`, `docs/26-domain-and-data-contracts.md` and the relevant detailed subsystem specification before implementation. `contracts/v2/INDEX.json` distinguishes executable reference schemas from draft provider/event/proposal schemas.

## Test-first acceptance criteria

- [ ] Write focused failing tests for this interface, including the failure cases below, and retain the exact red result.
- [ ] Implement the bounded deliverable without bypassing grants, scope projection, freshness or process/file identity.
- [ ] A written test without a run, a mock-only provider, a stale commit receipt or an uncompiled native component cannot satisfy a production support claim. Keep unsupported features visible in release notes.
- [ ] Run the full reference suite and any native/provider/host gates actually required by this issue. Retain OS, toolchain, command, exit status and exact revision.
- [ ] Update the capability matrix and handoff with implemented versus unverified states. No external account connection or user-file effect is implied by a passing unit test.

Finish with a concise receipt: source changes, tests, remaining constraints, dependency readiness and the next bounded step. Do not publish remote issues or merge without owner authorization.
