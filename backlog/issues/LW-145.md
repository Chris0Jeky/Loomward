# LW-145: Hostile names and metadata cannot create effects

Status: planned. Minted 2026-10-25 by the research programme (docs/51).
Milestone: M2. Priority: P1.
Dependencies: LW-118, LW-066.
Owner decisions HUMAN_TODO q-47 and q-48 (2026-10-25) bind this programme (docs/51 header).

## Scope
Build a hostile-name and hostile-metadata suite that runs across every projection. File and folder names, alternate stream names and metadata are untrusted data and cannot create an effect (docs/51 sections 2.6 and 5, throughout). The suite covers the MCP tools, the Ask panel's read-only tools and the native confirmation text, with bidi overrides, control characters, newlines, names that look like commands, paths or flags, and over-long names. Bidi and control characters are escaped in the native confirmation, and untrusted-evidence payloads are typed (docs/51 section 2.6).

## Acceptance evidence
No MCP or Ask path reaches a write. A suite asserts this for every tool in `crates/loomward-mcp` and every Ask tool, and any reachable write fails the build. The native confirmation escapes bidi and control characters, and a test shows a spoofed name rendering escaped. Names and metadata appear only as data in every projection. A failing case is a defect fixed in the same change; the test is not weakened to pass.
