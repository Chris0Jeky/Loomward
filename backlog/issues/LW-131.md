# LW-131: Read-only reclaim planner for a nearly full volume

Status: planned. Minted 2026-10-25 by the research programme (docs/51).
Milestone: M5. Priority: P0.
Dependencies: LW-119, LW-108, LW-009.
Owner decision context: HUMAN_TODO q-48 (2026-10-25) chose the Recycle Bin for archive originals, so the planner states the bin trap (docs/52 section 4).

## Scope
Build the read-only reclaim planner from docs/52 that answers which generated or re-obtainable data on a nearly full volume could be removed or relocated, how much would really be freed, how sure Loomward is, and which tool owns the cleanup. It extends the developer clutter provider (LW-119, rules version 1, project roots only) with rules version 2 for machine-level stores: shared Cargo target directories, package caches, model stores, virtual disks and `.git`-file agent worktrees (docs/52 section 3). Per-candidate reclaimable bytes reuse placement's verified-relief rule (LW-108), and any value that cannot be proven is null with a reason, never zero. The planner adds no file effect, no process effect and no execute path: owner steps are display text, and environment variable changes stay the owner's step (docs/52 section 9). It delivers lanes R1b to R1d of docs/52 section 8; the tool-agreement run (R1e, docs/51 X5) is a separate read-only lab step.

## Acceptance evidence
Synthetic fixtures under `fixtures/reclaim/` with names only (docs/52 section 7): one tree per class, hard-link groups that cross a candidate boundary (null reclaimable bytes), a placeholder inside a cache, a partial subtree (null sizes, never zero), a `.git`-file worktree, and a decoy for each class (a `target` folder with no `Cargo.toml`, a `models` folder of documents, a `node_modules` inside `target`), none of which may become a candidate. Output is byte-stable for the same catalogue. A test asserts the reclaim read requests no write, delete or rename and leaves `state.db` unchanged apart from the read's own bookkeeping. Phase P1 acceptance (docs/51 section 5): the plan on synthetic fixtures is exact, decoys are excluded and unknowns are never zero. Tool agreement (R1e, owner machine, inspection commands only: `cargo clean --dry-run`, `dotnet nuget locals all --list`, `pip cache info`, `uv cache dir`, `docker system df -v`; never `npm cache verify`, which garbage-collects): where the command reports sizes, Loomward's allocated bytes agree within 2% or the planner reports unknown; where it reports only a path, it confirms which folder is the cache; results are recorded as anonymised counts only. The desktop Reclaim view shows the four groups and the unaccounted line with no execute affordance (R1d; Playwright).
