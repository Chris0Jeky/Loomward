## Changes

- #434 MEDIUM-1: use `temp_store=FILE` only during the two forget VACUUMs. Restore the
  writer's original setting and its temporary grant/visibility views even after a failed rewrite.
  Other temporary listing tables are lazily recreated by their existing callers.
- #434 MEDIUM-2: retry pending cleanup between commands, with intervals 0.5, 1, 2, 4, 8,
  16, then 30 seconds. Persistent failures no longer rewrite every 500 ms; a busy command
  stream cannot starve recovery. The durable marker survives shutdown. A committed forget
  whose cleanup is pending returns `forget_scrub_pending`, with an explicit message, through
  the existing service error/UI path. No successful forget message is returned in that case.
- #434 LOW-1: marker-read errors propagate at open; the writer conservatively keeps recovery
  pending on a read failure. A failed marker deletion no longer counts as completed cleanup.
- #434 LOW-3: planted running/bulk damage is checked structurally before recovery can repair
  it; each case prints its violations. Only a clean child exit can mean an unreached crash
  point. A child panic is a distinct unexpected failure. Added a catalogue reader snapshot
  spanning forget, alongside the existing state-reader regression.
- #391 M2: scrub known migration copies by exact forgotten **grant IDs**, never by a path
  substring. This is stronger than component-prefix matching: a new grant of precisely the
  same path, a nested path and a sibling sharing its textual prefix all survive in the copy.
- #391 M3: report directory enumeration and unlink errors, continue sweeping other entries,
  and repeat backup cleanup at startup whenever forgotten grants exist. Include archived
  `catalog.corrupt-*` and `catalog.before-v1-*` databases and their sidecars.
- #391 linked-copy comment: reject nonregular, reparse, placeholder and hard-linked backup
  files before SQLite opens them. On Windows a checked file handle denies deletion/replacement
  while SQLite scrubs the copy. A native hard-link regression proves the external fixture
  remains byte-for-byte unchanged. Unsafe copies stay in place and produce an explicit error.
- #391 memory comment: unknown legacy shapes retain the fail-closed UTF-8/UTF-16LE check,
  now streaming with 64 KiB reads plus the longest-pattern overlap. Tests cover split matches,
  EOF, a missing marker, an error after successful reads and bounded read requests. Known
  shapes no longer need a whole-file byte scan. Startup discards unknown shapes because the
  forgotten path has already been redacted from live state.
- The SQL-identifier quoting comment was already addressed at the base; its existing regression
  remains in the service suite.

`cargo build -p loomward-catalog --example forget_perf`, then the `prepare` and `forget`
