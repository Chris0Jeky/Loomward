# Loomward v0.2: an evidence-based workspace control layer

9 October 2026. This is the second engineering pass over the original repository, not a replacement greenfield package. The original user request, research, code, tests, negative experiment and native foundation remain available. Documents 24-40 extend rather than silently supersede them.

## The thesis in one sentence

A personal computer becomes easier to manage when semantic organisation, physical residency and workload scheduling share evidence, but do not share unrestricted authority.

The differentiator should be a trustworthy model of the owner's work, not an impressive number of cleanup buttons. Loomward can know that a directory is a project, that a model is leased by a running worker, and that a backup is stale. It should use those facts to narrow choices. It should not interpret the existence of those facts as permission to act.

## What changed in this pass

The Python reference gained a scoped immutable SQLite catalogue, a protocol-independent tool service, a narrow dual-era MCP stdio server, an improved bounded allocation search, a multidimensional admission simulator and an ephemeral cooperative lease broker. The interface retains its seven original pages and adds Decision desk, Connections and Resource budgets. The live tier interface uses the new allocator; the standalone HTML retains its explicitly labelled greedy placement preview. The browser admission simulator has cross-language fixtures against Python.

These are real reference implementations. They do not implement the future persistent Windows index, native relocation, process enforcement, external provider adapters, multi-device sync or a production MCP gateway. The difference is carried into the UI, protocol outputs, issue status and handoff.

## The product shape

**Observe.** A scoped evidence layer records what was seen, when, where coverage ends and what remains unknown.

**Understand.** Human corrections, a light personal model and optional teacher proposals explain likely relationships without rewriting facts or elevating confidence into permission.

**Decide.** A decision desk compares alternatives, expected benefit, resource cost, missing evidence and recovery conditions. “Do nothing” is a first-class alternative.

**Coordinate.** Other tools can supply evidence, ask bounded questions and request cooperative resource reservations. Their permissions remain independent.

**Act, eventually.** A separate native broker validates a short-lived manifest and fresh object identities before each allowed operation. That broker does not exist in this build.

## Reading routes

For the idea and research direction, read 24, 25 and 33. For implementation, read 26-29 and 31-32. For the interface, read 30 and open the preview. For efficiency and risk, read 34-35. For execution, start with 37-40, `handoff/CHECKPOINT.json` and `backlog/INDEX.md`.

The owner does not need every subsystem to obtain value. The first usable release remains a Windows observation workbench with personal organisation and an explainable review queue. The new architecture makes that workbench useful to agents without requiring an autonomous organiser.

## Decisions this pass deliberately does not make

No real drive inventory or RAM/GPU measurement is assumed. No external service is connected. No hosted architecture, paid model, database server, kernel driver or replacement Windows shell is required. The working name and MIT source licence are retained; name/trademark clearance has not been performed. No repository, PR or issue was published remotely.
