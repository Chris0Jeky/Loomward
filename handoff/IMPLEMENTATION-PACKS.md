# Bounded continuation packs

The 64 issues are a dependency graph, not 64 parallel authorisations. The manifest is authoritative for each dependency. Keep shared schemas, native identity, IPC and operation states under one owner at a time.

| Pack | Starting issues | Deliverable and exit gate |
|---|---|---|
| A: establish the host | LW-001, LW-002, LW-064 | Windows reference evidence, compiling Rust and disposable native fixture lab; still no actions |
| B: trustworthy observation | LW-003 through LW-009, LW-016 | Stable identity/capabilities, catalogue, bounded scan, incremental reconciliation and truthful allocation |
| C: usable native product | LW-010, LW-011, LW-017 through LW-019 | Project groups, paged explorer, typed IPC and a real accessible Windows UI |
| D: personal learning | LW-020 through LW-029 | Private feedback lifecycle, taxonomy, reviewed teacher, embeddings experiment and calibrated shadow evaluation |
| E: storage reasoning | LW-030 through LW-034 | Oracle-tested placement, bidirectional hysteresis, bounded I/O, stable path contracts and active model leases |
| F: protection before relocation | LW-035 through LW-043 | Backup restore evidence, manifests/consent, durable copy journal, crash lab and only then the first gated move |
| G: desktop and applications | LW-044 through LW-049 | Known-folder/shortcut/virtual workspace/app providers, no blind Program Files moves |
| H: resource companion | LW-050 through LW-054 | Trustworthy metrics, trends, own-worker budgets and narrowly scoped reversible process policies |
| I: open-source operation | LW-055 through LW-058, LW-062, LW-063 | Redacted diagnostics, fair benchmarks, signed builds, read-only integration and observation-only field testing |
| J: evaluated extensions | LW-059 through LW-061 | Similarity, forecasting and developer providers only after evidence supports their value |

Some packs overlap after their dependencies pass. Do not parallelise authority-bearing schema changes with executor work before the contract is frozen and tested. A UI contributor may work against a versioned read-only fixture while the native team implements that protocol, but must not invent success states or arbitrary-effect APIs.

The initial publication helper imports only the first eight critical-path items, not the whole graph. Use stable local IDs in commit messages and map them to remote issue numbers after actual creation.
